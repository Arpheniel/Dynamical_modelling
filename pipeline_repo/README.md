# pipeline_repo — код моделирования статьи-2 (популяционно-орбитальный анализ)

Самодостаточный **кодовый** срез пайплайна статьи-2 («Популяционно-динамическое
моделирование галактик с рассогласованной кинематикой»). Здесь собран актуальный
код двух стадий моделирования — динамической (Schwarzschild) и
популяционно-орбитальной (BVLS-разложение карт возраста/металличности по
орбитам) — плюс газовая диагностика для раздела «Обсуждение». Цель — иметь
один аккуратный набор скриптов, чтобы повторить проделанную часть на **других
галактиках**.

> **Только код, без данных.** Тяжёлые входы/выходы (FITS-кубы MaNGA, MGE,
> архивы орбит `*.npz`, папки `orbits_*`, кэши) сюда не копировались — см.
> «Что НЕ входит» ниже.
>
> **Код не редактировался** — файлы перенесены побайтово (целостность сверена по
> MD5). Параметры под конкретную галактику зашиты внутри скриптов; что менять для
> новой галактики — в разделе «Адаптация».

Источники — последние рабочие версии на 2026-06-06, проверенные по хэшам.
В проекте было много дублей; брались самые свежие, дублей-кандидатов в
репозиторий не клалось. Два места, где «свежее» расходилось с пакетом `handoff/`
(важно — устаревшие копии там реально были):

| файл | взят из | почему |
|---|---|---|
| `wirb_C_LEDA.py` | `leda_final_C/` (06.06) | в `handoff/` лежала версия 02.06 **до** фикса ориентации плотность↔кинематика |
| `forstand_C_LEDA_2220522.py` | `LEDA/` (01.06, 42 КБ) | новее версии в `handoff/dynamics_C/` (31.05, 39 КБ) |

Остальное: химия/фигуры/диагностики — из живых `pgc_final_C/`, `leda_final_C/`;
динамика — из `PGC/`, `LEDA/`; `schwarzlib_really_fixed.py` идентичен во всех

## 3. Логика пайплайна

```
MaNGA DR17 куб ──NBursts + E-MILES(BaSTI)──> results_*.fits         (вне репо, сервер)
                                                │ карты V,σ,h3,h4, возраст, [Fe/H], потоки эмиссий
DESI z-band ──MGE──> потенциал ─┐               │
                                ▼               │
            [01_dynamics] forstand_C: 1D-скан V_max при космол. фикс. r_s
            (AGAMA/Forstand, 20000 орбит, √Υ-trick) ──> архив .npz (веса орбит,
                                                        Rmean, λz, DYN_COMP_LOSVD)
                                │
            карты возраста/[Fe/H] (fits) + веса орбит (.npz)
                                ▼
            [02_population_orbit] chemo_unified: BVLS (λ=0.01, границы по
            диапазону данных) ──> φ^T_j, φ^Z_j по ячейкам (R, λz)
                                │
        ┌──────────────┬────────┴───────────┬──────────────────┐
   obs/model/        radial_profiles      mc_stability      [wirb_C → losvd_and_surface_density]
   residuals          (+ MC, N=50)                          [fig6_C → Rad_vs_Lambda_z]
```

**NBursts** (полная спектральная подгонка, сетка E-MILES) — отдельный пакет на
удалённом сервере, в репозиторий не входит. Стадия 2 принимает его выход
(`results_*.fits`) как данность.

Ключевые методические параметры (зашиты в скриптах; см. также
`../handoff/chemistry/FINAL_C_RESULTS.md`):
- сетка орбитальной плоскости `(R, λz)` — **21×21**; границы компонентов **±0.35**
  по λz (биннинг через `int(round(...))`);
- регуляризация BVLS **λ=0.01** (выбрана по `lambda_scan.py`);
- **границы BVLS = диапазон наблюдаемых карт ± малый запас**, НЕ края сетки
  E-MILES;
- число орбит **20000**, `model_index = 5` (индекс Υ финальной модели);
- Монте-Карло **N=50** реализаций возмущения входных карт.

## 4. Зависимости и запуск

Окружение: Python 3.11 + `numpy scipy matplotlib astropy agama`
(+ `PyMuPDF`/fitz опц. для рендера PDF→PNG). На Windows-консоли —
`PYTHONUTF8=1` (иначе падает на не-cp1251 символах в выводе).

**schwarzlib.** Скрипты импортируют `schwarzlib`. Положить рядом (или в
`PYTHONPATH`) именно `00_lib/schwarzlib_really_fixed.py`, переименовав в
`schwarzlib.py` — это модифицированная версия, на ней посчитаны все результаты;
со стоковой `schwarzlib` из AGAMA числа разойдутся.

**Рантайм-раскладка.** Репозиторий организован по ролям (для понимания); сами
скрипты ожидают «плоскую» рабочую папку: код + `schwarzlib.py` + данные в одном
каталоге (как в исходных `pgc_final_C/`, `leda_final_C/`). Для запуска: собрать
рабочую папку галактики из нужных скриптов (`_common/` + соответствующий
`PGC/` или `LEDA/`), положить туда `schwarzlib.py` и данные, поправить в
`chemo_unified.py` имена входных файлов.

Порядок (пример для одной галактики, после прихода динамической модели):
```
# Стадия 1 (кластер): скан χ²(V_max) и запись орбит лучшей точки
bash launch_C_PGC.sh            # → grid_chi2_*.npz + архив модели M..._GH_*.npz + orbits_*
bash show_status_C.sh           # мониторинг

# Стадия 2 (рабочая машина), плоская папка с данными и schwarzlib.py:
PYTHONUTF8=1 python lambda_scan.py            # подобрать λ (один раз)
PYTHONUTF8=1 python chemo_unified.py          # BVLS + obs/model/residuals/radial/mc-фигуры
PYTHONUTF8=1 python wirb_C_PGC.py             # losvd_and_surface_density
PYTHONUTF8=1 python fig6_C_PGC.py             # Rad_vs_Lambda_z
PYTHONUTF8=1 python mc_components.py          # σ_MC по компонентам
PYTHONUTF8=1 python integral_characteristics.py --galaxy PGC
```

## 5. Адаптация под новую галактику

Пер-галактические значения зашиты внутри скриптов (не через конфиг-файл),
поэтому новую галактику заводят копией одного из комплектов (`PGC/` или `LEDA/`)
с правкой констант. Что менять:

**`01_dynamics/forstand_C_*.py`** (есть подробная док-строка в шапке файла):
- `distance` / `arcsec2kpc`, наклон `incl`, позиционный угол `gamma1` (PA);
- базис плотности — `DensitySphHarm` (сфероид-доминантные) или
  `DensityCylindricalLinear` (диск-доминантные);
- MGE-файлы поверхностной яркости, файл кинематики, бины Вороного;
- каталожная `logM*` (через неё считается космологический приор на `r_s` и
  центр скана по `V_max`: Moster+13 SHMR → Dutton & Maccio 2014 c–M, H0=67.7);
- `Mbh` (фикс. 1e7), `numOrbits`, `regul`.

**`02_population_orbit/<gal>/chemo_unified.py`**:
- `GALAXY`, имена входов (`results_*.fits`, архив `M..._GH_*.npz`, `orbits_dir`);
- `model_index` (индекс Υ финальной точки);
- **границы BVLS** — задать по диапазону наблюдаемых карт данной галактики
  (возраст ±0.5 млрд лет, [Fe/H] ±0.2 dex), а НЕ по краям E-MILES;
- `incl` в `chemo_unified` = угол поворота orbit-карты = **90° − i_галактики**
  (для PGC 48, для LEDA 63) — это поворот, не наклон (помечено в коде).

**`wirb_C_*.py`, `fig6_C_*.py`**: геометрия проекции той же галактики (углы,
`agama_gamma`), имена архива/орбит/мозаики DESI/`results_*.fits`/бинов.
⚠️ Ловушка кэша плотности: имя `density_cache_*` не кодирует `agama_gamma`/углы
проекции — при их смене кэш чистить вручную (иначе `wirb` отдаст старые карты).

Справочные значения двух уже посчитанных галактик:

| | PGC 35706 (8992-3704) | LEDA 2220522 (8254-1902) |
|---|---|---|
| наклон i | 42° | 27° |
| PA (gamma1) | 0° | 40° |
| базис плотности | DensitySphHarm | DensityCylindricalLinear |
| r_s (космол. фикс.) | 71.6″ | 30.6″ |
| финализация V_max | argmin χ² (162 км/с) | приор (125 км/с) |
| model_index (Υ) | 5 (Υ≈10.25) | 5 (Υ≈4.78) |
| границы BVLS возраст | [1.5, 14.1] млрд лет | [1.0, 5.5] млрд лет |
| границы BVLS [Fe/H] | [−0.7, +0.4] dex | [−1.0, +0.3] dex |
| incl в chemo (90−i) | 48 | 63 |

## 6. Что НЕ входит (и где лежит в проекте)

- **NBursts** (полная спектральная подгонка + E-MILES) — отдельный пакет на
  удалённом сервере. Его выход `results_*.fits` — вход стадии 2.
- **Данные**: FITS-кубы MaNGA, MGE (`mge_*`), бины Вороного (`bins_*`),
  DESI-мозаики (`mosaic-*-z-CCD*`), архивы орбит `M..._GH_*.npz`, папки
  `orbits_*`, `grid_chi2_*.npz`, `results_cache_*`, `density_cache_*`. Лежат в
  рабочих папках `PGC/`, `LEDA/`, `pgc_final_C/`, `leda_final_C/` и в
  `handoff/dynamics_C/heavy/`.
- **Легаси/альтернативный код** (намеренно не переносился): `adamet_x_forstand_*`
  (старый AdaMet MCMC), `run_forstand_grid_*`, `forstand_grid_R1_*` /
  `forstand_grid_verify_*` (2D-грид (r_s,V_max) — альтернатива подходу C),
  `wirb_clean*` / `wirb_LEDA_clean*` и `fig6_*_fixed`/`fig6_leda_v2` (заменены
  на `wirb_C_*`/`fig6_C_*`), старые подходы в `*_CD/`, бэкап `handoff (2)/`.
  Всё это остаётся в исходных папках проекта.
